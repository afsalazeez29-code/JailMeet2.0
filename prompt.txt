The build error is cleared. /planmode error is gone , but the another issue cam econtents not showing , do not touch the code only give the about the problem and explantaion of solution ok, dont edit . The new issue is most likely this:

Your `app/page.tsx` was rebuilt after the UTF-8 corruption. The build error is gone, but some landing page content may not show because the legacy landing page depends on JavaScript animation libraries, especially `AOS`.

In the old landing page, many elements have:

```tsx
data-aos="fade-up"
data-aos-delay="100"
```

The `aos.css` file hides those elements first, then the AOS JavaScript adds an active class like:

```html
.aos-animate
```

If the AOS JavaScript is not loaded/initialized, those sections can stay invisible.

So the problem is probably:

```text
AOS CSS is loaded, but AOS JS is not initializing.
```

Solution concept:

Restore/load the old landing scripts in `app/page.tsx`, especially:

```text
/legacy/landing/assets/vendor/aos/aos.js
/legacy/landing/assets/vendor/bootstrap/js/bootstrap.bundle.min.js
/legacy/landing/assets/vendor/purecounter/purecounter_vanilla.js
/legacy/landing/assets/vendor/glightbox/js/glightbox.min.js
/legacy/landing/assets/vendor/swiper/swiper-bundle.min.js
/legacy/landing/assets/js/main.js
```

Then initialize AOS after scripts load:

```tsx
window.AOS?.init();
```

Alternative solution:

Remove all `data-aos` attributes from the landing page, but that changes old behavior/animation, so the better fix is to restore the legacy JS loading.

Also one more important point:

Because `app/page.tsx` had been overwritten with search output, the current page was reconstructed. If some old sections/content are missing, that is not a CSS issue. It means the original landing JSX content was lost and needs to be restored from the old `index.php` or previous backup. Fixed the landing asset/AOS issue.
