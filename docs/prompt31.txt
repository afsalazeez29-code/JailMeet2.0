ISSUE 2 — AOS animation library not initialized (13 invisible elements)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Confirmed cause: AOS CSS is loaded and sets all `data-aos` elements to opacity: 0
by default. 13 elements on the landing page use data-aos attributes. But aos.js
itself and AOS.init() are never actually loaded/called, so those 13 elements never
receive the .aos-animate class and remain permanently invisible. This is why content
appears "missing" even though it exists in the JSX. The footer stays visible only
because it does not use any data-aos attribute — this confirms the diagnosis.

Fix — in page.tsx (or LandingAssets.tsx, whichever actually mounts landing scripts):

1. Load these scripts ONLY on the landing page, in this exact order:
   bootstrap.bundle.min.js
   aos.js
   purecounter_vanilla.js
   glightbox.min.js
   swiper-bundle.min.js
   main.js

   Correct absolute paths (verify each exists at these paths before referencing):
   /legacy/landing/assets/vendor/bootstrap/js/bootstrap.bundle.min.js
   /legacy/landing/assets/vendor/aos/aos.js
   /legacy/landing/assets/vendor/purecounter/purecounter_vanilla.js
   /legacy/landing/assets/vendor/glightbox/js/glightbox.min.js
   /legacy/landing/assets/vendor/swiper/swiper-bundle.min.js
   /legacy/landing/assets/js/main.js

2. After aos.js has loaded, initialize it:
   (window as any).AOS?.init({
     duration: 600,
     once: true,
   });

3. If landing content renders dynamically after mount, also call:
   (window as any).AOS?.refreshHard();

4. Do not add these scripts to any route other than the landing page.
5. Do not add duplicate script tags if any of these are already loaded elsewhere.

Do NOT choose the alternative of removing data-aos attributes or disabling AOS CSS —
initializing AOS correctly is the required solution, since it preserves the original
intended animations rather than deleting them.
