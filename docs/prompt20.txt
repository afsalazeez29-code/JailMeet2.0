PHASE 6 — CREATE VISITOR APPOINTMENT
==================================================

Create:

POST /api/visitor/appointments

Access:
- authenticated
- VISITOR role only

Request body:

{
  "prisonerId": "...",
  "appointmentAt": "2026-07-25T10:30:00.000Z",
  "reason": "Family visit"
}

The frontend must not send:

- visitorId
- officerId
- status
- role
- userId
- officerNote

Use the authenticated visitor identity from the verified JWT.

Required backend workflow:

1. Verify JWT.
2. Confirm VISITOR role.
3. Validate request with Zod.
4. Resolve authenticated User to VisitorProfile.
5. Confirm the selected PrisonerProfile exists.
6. Confirm appointment date/time is in the future.
7. Check duplicate booking rules.
8. Create appointment with status PENDING.
9. Return a safe appointment response.

Zod rules:

prisonerId:
- required non-empty string

appointmentAt:
- required ISO datetime string
- service must confirm it is in the future

reason:
- trimmed string
- minimum 5 characters
- maximum 500 characters

Use a strict object and reject unknown fields.
