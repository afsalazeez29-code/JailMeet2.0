SECURITY RULES (apply throughout, verify explicitly in final report)
============================================================

- Only ADMIN can create/edit Officer or Prisoner accounts
- Admin identity comes from JWT only
- Backend assigns role (OFFICER/PRISONER) — never accepted from the frontend
- Password is hashed with bcrypt before storage — never stored, logged, or returned in plaintext or as a hash
- User and profile creation happen in one Prisma transaction — no partial/orphaned records possible
- Unknown fields are rejected on every create/update endpoint (.strict() Zod schemas)
- Duplicate email is blocked (both application-level check and DB constraint fallback)
- Role cannot be changed via any endpoint in this task
- IDs (User ID, Profile ID) cannot be changed via edit
- Password data is never returned in any API response
- Frontend validation is a UX nicety only — backend Zod validation is the real authority
