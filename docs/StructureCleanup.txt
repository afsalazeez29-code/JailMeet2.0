Requirements for dashboard.service.ts:
Provide typed functions for:
- getAdminDashboard()
- getVisitorDashboard()
- getOfficerDashboard()
- getPrisonerDashboard()

Each function must:
1. Call the correct route under NEXT_PUBLIC_API_BASE_URL.
2. Send the Bearer token in the Authorization header.
3. Parse the actual backend response structure.
4. Return only typed dashboard data (using the types created in Phase 2).
5. Preserve HTTP status information for 401 and 403 handling — the caller needs to know which status occurred.
6. Handle malformed or non-JSON responses safely (no unhandled exceptions on bad JSON).
7. NOT redirect directly inside the service — no router access here.
8. NOT access React router APIs (no useRouter, no next/navigation imports in the service files).
9. NOT contain UI state (no useState, no loading/error state — that stays in the component).
10. NOT silently swallow errors — always surface them to the caller in a typed, predictable way.

Do not create Axios dependencies unless the project already uses Axios for this frontend. Prefer the existing fetch-based approach already in use.
